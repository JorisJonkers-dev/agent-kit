## cap-opencode

`opencode acp` has no capability-profile flags (`--help` only shows `--login`), so launching it restricted to read/read-web/write-scoped/write profiles is NOT POSSIBLE natively. The config schema defines `permissions` (read/edit/bash/websearch/skill etc. with ask/allow/deny) and `policies` (tool.use/websearch.use/mcp.use/etc. with allow/deny), but whether ACP honors them at launch is UNVERIFIED. Config home can be redirected per launch via `OPENCODE_CONFIG_DIR` (SUPPORTED, confirmed in binary strings). Skills default to `~/.config/opencode/skills` and can be extended via the `skills` config field or by changing `OPENCODE_CONFIG_DIR`; Claude Code skills can be disabled with `OPENCODE_DISABLE_CLAUDE_CODE_SKILLS`. Project config loading is SUPPORTED (disabled via `OPENCODE_DISABLE_PROJECT_CONFIG`), but its override precedence versus launcher/global config is UNVERIFIED. Secrets exist in `service.json` and `opencode.json` but are not printed.

## cap-agy

A launcher CAN start `agy acp` with per-profile config via `--gemini-dir`/`--app-data-dir` (empty home ⇒ no MCP, isolated settings/hooks; skills follow appDataDir; auth must be re-established per home). ACP has no `--settings`/`--mode` flags (verified error). Profiles 1,2: SUPPORTED only as deny-at-execution — `PreToolUse` hook `"decision":"deny"` with tool-name regex matchers plus `permissions.allow`-style rule grammar (`command()`, `read_file()`, `write_file()`, `read_url()`, `execute_url()`, `mcp()`); ACP's `disableBuiltInTools` session param is a no-op ("not supported by the default agent yet"), and no `search_web` rule kind exists (hook-only; UNVERIFIED). Profile 3: SUPPORTED via workspace confinement (session cwd/`--add-dir`, non-workspace file access deny, path-scoped `write_file(<abs>)`) + `--sandbox` (Seatbelt, network-off) for shell; without sandbox, shell path-scoping needs OS enforcement (agy provides it). Profile 4: SUPPORTED (`permissionPreset` NONE/DEFAULT/AUTO/TURBO/REQUEST_REVIEW, `sandboxMode`, `toolPermission`, `autoExecPolicy`, `command()` lists; sandbox toggled separately). Project `.agents/` customizations outrank global config (documented priority); per-project permissions exist (desktop docs + CLI projects files; CLI precedence partly UNVERIFIED). Enterprise admin_settings.json would outrank launcher config.
