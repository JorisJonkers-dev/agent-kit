## 1. Goal

The owner found Gold Band (`github.com/diodeme/Gold-Band`, v0.19.1): an AGPL-3.0 desktop client for coding agents over the Agent Client Protocol (ACP), with a JSON workflow DSL, "profiles" (role prompts), skill sync and MCP injection. The owner's priority is **adoption**: configure Gold Band on this Mac with all their agents, MCP servers, roles and skills, keep agent-kit's own runner, hooks and model gateway underneath until they are certain, and contribute upstream to Gold Band as an open-source developer. A LiteLLM proxy for pay-per-token keys is also wanted.

`goldband-reference.md` is the owner-supplied description of Gold Band (not verified; some numbers differ from reality, see §4).

## 2. Decisions the owner made (from a grill, 2026-11-06)

- **Posture:** keep our runner, gateway, hooks and ledger underneath. Use Gold Band as a front-end and contribute upstream. Drop our own pieces only when certain. "Certain" means: hooks and gates hold for Gold-Band-launched agents, and the daily drivers (Vibe, OpenCode, Antigravity, Hermes, Pi) run reliably over ACP. Headless and cloud are not criteria for now.
- **Codex** (employer-metered, needs a grant, ADR-0008): banned from all Gold Band config.
- **No OpenRouter**, ever. OpenCode only via `opencode-go/...`, never `opencode/...` (Zen).
- **Gold Band is never used on work (nedap) repos.** It cannot enforce the gateway's data policy (ADR-0007). Both Claude identities may be used elsewhere: work `~/.claude` (id `claude-acp`) and personal `~/.claude-personal` (id `claude-personal`, selected by `CLAUDE_CONFIG_DIR`). Personal Claude is never used on work repos.
- **Permissions:** agents' default modes, `auto_accept` off. **Exception:** Pi runs full tools, in throwaway repos only (Pi has no permission prompts).
- **Config ownership:** the app owns `~/.gold-band` (it rewrites `workflows.json` on load); we snapshot into the repo later.
- **MCP:** move the fleet into Gold Band, but only after a same-name overlap test (see §7). Token-bearing servers go through a keychain stdio proxy, never plaintext in `settings.json`.
- **Skills:** one source dir `~/.gold-band/skills` with per-agent symlinks. The migration plan is not designed yet (§7).
- **Roles:** 12 profiles: reuse six built-ins (`pf-builtin-plan`, `-dev`, `-dev-test`, `-test`, `-accept`, `-grill`), plus five new from our critique roles and one merged verifier.
- **Licence:** relicense agent-kit to AGPL-3.0-only when code first crosses to Gold Band. The owner should separately check employer IP terms (not judged here).
- **First upstream contribution:** a standalone CLI workflow validator. The DSL validator is already a library crate (`src/dsl/mod.rs`, `validate_workflow`, `validate_workflow_snapshot`) and the CLI has only `run` and `continue`.
- **LiteLLM:** a proxy for pay-per-token keys, including `opencode-go` if it issues an API key (**unverified**, the owner believes so). Docker and `uv` are installed. Subscription logins (Claude Max, Google, OpenCode Go subscription auth) cannot be routed through it.
- **Experiment:** one day. Run first as a cheap read-only investigation workflow, then one critique stage. **Changed during the spec review (section 10):** the owner chose to have the Gold Band spec-stage template replace the runner with one worker node per critic, as a labelled degraded path beside the real runner. That is a deliberate exception to the earlier rule "kill the experiment if a guarantee of ADR-0001 or ADR-0004 is lost"; the lost guarantees are listed in the spec (story 38) and the path is limited to personal repositories.

The same decisions are in the project memory file `gold-band-adoption-decisions.md` (Claude project memory for this repo).

## 5. Security review results

Three investigations; the owner decided to build from source because of the first.

- **Provenance (worker-reported):** the release was built by a Release Please run from commit `4b804c4`, but tag v0.19.1 now points at `987fc3e`. The maintainer rewrote history on 2026-10-30 and re-pointed every release tag. The two trees differ in 12 files, all an internal hostname swapped for `example.com`. There are no attestations, SBOM or SLSA. Actions are pinned by mutable tag, signing is ad-hoc, and there is no notarisation. `release.yml` (manual rebuild only) checks out tooling from the dispatch ref, not the tag. The release `.dmg` was never re-uploaded after publishing. **verified** by the writer: a string comparison of the release binary and the local build showed the only substantive difference was `wnpm.weoa.com:8001` against `wnpm.example.com:8001`, consistent with the scrub. This is evidence, not proof (the binaries cannot be byte-identical).
- **Source audit of `987fc3e` (worker-reported, grep-and-read only, web UI not audited in depth):** no telemetry on by default (metrics and feedback endpoints exist but are off), no obfuscation, no download-then-execute, no committed binaries. The updater polls GitHub and `critical: true` updates download silently (dead in our build). The keychain is used only for WeCom credentials. MCP `clientSecret` and headers are stored in plaintext in `settings.json`. Agent subprocesses inherit the full environment (no `env_clear`). `acp.raw.jsonl` stores prompts, code and tool output in plaintext with default permissions. The CSP is `null`. There is no listener except a debug-only heap port on Windows.
- **Observed on this machine (verified):** Gold Band itself made no network connections. Its child processes did: `npm exec claude-agent-acp@0.87.0` (npm registry) and `claude` (Anthropic). Gold Band spawns the adapter and `claude` with cwd `/`, and runs probe `session/new` calls with `workspace_root="/"` about once a minute. This is the likely cause of the macOS prompts for Downloads and network-volume access (inference; the prompts were denied). Fix idea: raise it upstream, or wrap the command so the process starts from a scratch directory.
- Supply-chain review by five Vibe workers: all said "install with mitigations"; no malicious crates or packages identified. Their noise (calling `rmcp` a "remote management control protocol", treating the AGPL as a security risk) was discarded.
